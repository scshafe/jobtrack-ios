# jobtrack-ios: the owner's brief

The owner's request, 2026-10-20: an iOS client for
[jobtrack](https://github.com/scshafe/jobtrack), the owner's job-search
system of record.

## How the app changes jobtrack: requests, never writes

jobtrack keeps its CLI as the **only writer** of its store. The app never
writes the store, directly or through a write API. It **files requests**
(move a card, pursue or dismiss, approve a gate, capture a posting URL) to a
jobtrack API; jobtrack's worker validates each request and runs the matching
CLI operation. Until a request is applied, its card shows **pending**; a
request jobtrack refuses shows why.

The jobtrack side (the request queue, the board read model, the door) is
designed by jobtrack's agent in jobtrack's
`docs/design-mobile-and-discovery.md`. This repository follows that design.
Coordinate through agent-request issues to jobtrack; never edit jobtrack from
here.

## v1

- **Board.** A kanban board with **fixed lifecycle columns**: Found,
  Pursuing, Preparing, Applied, Interviewing, Offer, Closed, each mapped to
  jobtrack's real states. A drag is allowed only where jobtrack allows that
  transition. Gated moves (submitting an application, an offer decision) ask
  for confirmation first.
- **Needs me.** A queue of what waits on the owner: pursue or dismiss
  decisions, approvals, follow-ups that are due.
- **Push alerts.** Native iOS push (APNs), matching mailroom-ios's approach
  (mailroom's `docs/design-inbox-zero.md`, "Push (APNs)"): the server sends
  through Apple; a push carries no job content, only an opaque id the app
  resolves over the tailnet.
- **Share-sheet extension.** Captures a posting URL from Safari, LinkedIn or
  any app that shares a link, and files it as a capture request.

## Sign-in

Pocket ID, native OIDC authorization code with PKCE as a public client, and
`Authorization: Bearer <id token>` on every API call, accepted by an
oauth2-proxy door: the same pattern as homemesh's capture app (Pocket ID
client `homemesh-capture`; homemesh's `docs/deploy.md`, "The capture app's
sign-in"). The owner session provisions the door and the Pocket ID client.

## Fixed points for this repository

- SwiftUI, iOS 26, iPhone; bundle id `com.scshafe.jobtrack`. The Xcode
  project is generated by XcodeGen from `project.yml`, as mailroom-ios's.
- The app's logic lives in the `JobtrackKit` Swift package, unit tested with
  `swift test`; the app target is the UI.
- **Public repository, MIT licence.** Never commit personal data, job or
  store contents, screenshots with real data, tokens, or the tailnet name
  (write `<tailnet>`). Fixtures are synthetic.
- Built and run by the owner on the Air in Xcode. No deploy lane. CI runs
  because the repository is public, on GitHub-hosted runners only.

## How the work starts

The app's agent writes `docs/design.md` as its first PR, with an **"Owner
decisions"** section listing what the owner must decide. Nothing is built
past the skeleton until the owner accepts it.
